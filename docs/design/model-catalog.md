# 模型目录元数据功能设计

> 状态：**待实现的专题设计**。本文“现状”仅描述已核对的源码；“提案”是拟新增契约，不代表当前版本已经具备。编写期间仅做静态核对，未启动服务、构建或运行测试。
>
> 上位设计：总体设计将本专题列为 P1，并要求只展示有依据的数据、保持旧配置和客户端兼容。

## 1. 目标、边界与决策

**目标**：调用方在原有凭据过滤后的 `GET /v1/models` 上，按需得到可核验的模型展示信息；WebUI 模型选择器能展示这些信息，不得因此增加、删除或改变可调用名称。信息来自同一份 models.dev 快照，是第三方目录的**参考声明**，不等于 AMKR 对当前 Provider 的能力、窗口或可用性的保证。

**本期做**：可选的 `display_name`、`reasoning`、`context_window`、`max_output_tokens`、`modalities`、`kind` 契约；复用已存在的目录抓取和缓存；保留既有 `owned_by`；把未知、冲突、歧义视为缺失；在 Playground 等消费 `/v1/models` 的选择器中展示有限信息。

**不做**：不以目录作为授权或路由判据；不自动修改模型配置、默认模型或 Agent 本地文件；不推测价格、窗口、能力，不用元数据限制请求；不提供全量模型导出、额外远程抓取、用户自定义源或管理写 API。本期没有元数据持久化与用户配置：无新增配置键、迁移或修复步骤，服务器重启后缓存重新预热。

重点兼容决策：`owned_by` **现在就是必有字段且恒为 "auto-model-key-router"**，不是可追加的新字段，也不能改成上游公司；新增字段只在显式请求时出现。`kind` 的字段契约先定义，但现有 models.dev 资料尚未核实有能直接证明 AMKR 端点类型的权威字段；本期若无法取得明确证据就**始终省略**，不能把现有名字正则推断冒充已知事实。

## 3. 用户流程（提案）

1. 管理员配置模型、上游目标及访问范围，操作方式保持现状；目录由既有后台机制预热，无需另填 URL 或密钥。
2. 调用方使用原有凭据请求 `GET /v1/models?include=metadata`；服务端先按原有身份和名字过滤，再仅为结果中的名字尝试匹配当前内存快照。
3. 客户端先显示可调用的原始 ID；有有效显示名时可在旁边展示，已知窗口和模态显示为目录参考。匹配不到、目录未就绪或字段冲突时，列表与调用照常，未知信息显示“— / 暂无资料”，不显示为“无能力”或 0。
4. 目录更新失败时继续使用最近一次成功快照；需要了解全局刷新情况的管理员可看现有价格目录状态。普通调用方不获得目录全貌、内部目标或刷新错误详情。数据恢复后后台自动更新，不要求用户重配或重启。
5. 用户应用 Claude Code/Codex/Pi 集成时，本期沿用原有生成及备份/回滚行为；不因目录更新自动写用户文件。未来若让 Agent 消费元数据，须另行验证各客户端版本和缺省行为，尤其是 Pi 现有固定窗口问题。

## 4. 数据模型、匹配与配置（提案）

### 4.1 内部索引与配置

扩展既有 `pricing` 的只读 snapshot，在**同一次** models.dev 响应解析后，增加按**目录原始模型 ID 精确、区分大小写**索引的元数据候选集合；每条记录保留来源 Provider 键、原始模型 ID 及各字段的“有值/无值”，这些内部定位数据不在受限响应中输出。保留现有价格索引和 `modelkind` 索引，不复用其会去前缀、日期/版本及跨供应商合并的有损归一化结果当精确身份。相同 ID 在多个目录 Provider 下出现是多个候选，不能按 map 遍历顺序选一条，也不按“最低价”推断能力。

不新增用户配置和端点；既有 `PricingFetch` 为 nil 时依旧不出网（`internal/server/pricing.go:77-87`）。生产还是固定 HTTPS 源；除固定源的响应外不请求用户输入的地址，不把请求模型名或凭据发送给 models.dev。配置热重载不应触发单独的网络抓取。

### 4.2 对外字段

| 字段 | JSON 类型及输出条件 | 值来源/语义 |
| --- | --- | --- |
| `id` | string，必有，原样 | 既有授权后的对外调用名，绝不改写。 |
| `object` | string，必有，`model` | 既有对象类型，不是模型用途。 |
| `owned_by` | string，必有，`auto-model-key-router` | 既有兼容字段，表示目录项由 AMKR 发布，不声称是模型作者；不用目录 Provider 名覆盖。 |
| `display_name` | 非空 string，可选 | 所有候选的 `name` 经校验后一致才输出；不以 ID 冒充来源显示名。 |
| `reasoning` | boolean，可选 | 所有候选显式 `reasoning` 为相同布尔值才输出。`false` 与缺失不同；仅表示目录声明，不证明该代理路径支持推理。 |
| `context_window` | 正整数，可选，单位 token | 对应所有候选一致的 `limit.context`，不是当前服务的实测或硬约束。 |
| `max_output_tokens` | 正整数，可选，单位 token | 对应所有候选一致的 `limit.output`；若两种窗口均已知且输出大于上下文，两字段均省略并记录聚合校验失败，不猜哪个正确。 |
| `modalities` | 对象，可选：`input?`、`output?` 分别为非空字符串数组 | 分别读取同名数组，各候选该方向均完整且集合一致才输出；允许 `text/image/audio/video/pdf`，排序去重。一个方向未知只省略该方向；两方向均未知则省略整个对象。 |
| `kind` | string，可选；枚举 `text/image/video/tts/stt/embedding/rerank` | 仅在有**明确类型事实**、与身份安全匹配、且多候选一致时输出；不输出 `unknown`、空串或猜测。现有目录模态推导和名字规则不是足以声明真实端点类型的事实；来源未确认前本期省略。多类型时不任意选 primary，本期省略。 |

对名称使用 UTF-8、去除两端空白后长度 1–128 字节，拒绝控制字符；数值必须为 JSON 数字、有限、整数、`1..9007199254740991`。空、缺失、`null`、错误类型、超限均是未知；不把它们转换为 `false`、`0` 或空数组。如果模态数组含非字符串、空项或白名单外的项，该方向整体省略，不能删掉不认识的项后声称剩余集合完整。可在内存里逐字段校验；未知字段或上游新增字段直接忽略。

models.dev 公开 JSON 的示例可见其 `name/reasoning/limit.context/limit.output/modalities` 结构：[models.dev API](https://models.dev/api.json)。这是外部可变来源，不保证当前部署模型能力或后续 schema 不变；实现需以固定夹具覆盖缺失、错误及变化。`kind` 并非因源数据有 `modalities` 就天然可证实。

### 4.3 身份匹配与冲突

按以下顺序执行；宁可少给信息，也不拼凑一个貌似完整的模型：

1. **先过滤名称，后匹配**：只遍历现有处理器得到的 `names`。绝不能遍历全量目录再按前缀/名称过滤；目录不决定名字集合、顺序或权限。
2. `unified-model` 一律不补元数据。工作空间推理 Key 的候选名若是**本空间**任务名，即便同名真实模型也不补；完整权限凭据则为避免跨端点和空间歧义，对与任意空间任务重名的项不补。Access Key 无权使用任务，元数据匹配**不读取任何空间的任务集合**：只对已授权配置模型的对外名提供目录参考，不声称该名字在某个请求工作空间实际可调用。这样受限 Key 不能通过元数据有无探测其他空间是否存在同名任务；既有 `/v1/models` 和调用侧任务优先级不变。所有判断使用当前 lease 的配置。
3. 其他名字须精确命中一个已配置模型 ID 或别名；为防通过别名暴露未授权的真实 ID 或内部上游名，**只使用该已授权的对外名字本身**做目录精确键，不以解析后的真实 ID 查询。若模型配置端点转向则不补；用于判断上游名的目标集合必须是该凭据可用的启用目标：完整权限及工作空间推理 Key 取全部启用目标，Access Key 只取 `AllowsProvider` 允许的启用目标。集合非空且每个目标的 `KeyConfig.UpstreamModel` 均与对外名逐字相同时才补信息；不能检查受限 Key 无权使用的 Provider 目标以决定响应，避免借字段存在性泄露其变更。别名与真实 ID 不同或代理改名时通常没有元数据，这是有意的安全退化。目录信息仍仅描述公开同名模型，并不保证该目标实施了目录中的能力。
4. 按该对外名找目录的全部 Provider 候选；来源中同一键下的 `id` 若存在且与键不一致、模型对象形状无效，视作不可信候选，阻止对应项输出，而不是悄悄跳过后取另一条。无候选则全部字段缺失。每个字段只有**全部候选都有效且值一致**时才输出；对数组先按白名单规范化排序再比较。任何缺失或冲突都只影响相关字段，不从另一候选“补齐”。
5. 这些规则不证明本机代理实际实现与第三方相同，信息仅标为“目录参考”；不暴露候选 Provider、目标名、Key、详细冲突或来源内部路径。遇到模型有多个路由目标、同名不同厂商或私有改名时，按上述规则保守省略。

备注：`kind` 不能用 `modelkind.Primary()` 直接代填，因为当前结果包含有损 ID 合并与名字规则，并且模型可以有多种类型。以后如取得权威的显式类型来源，先明确 schema、映射和一致性测试，再开启输出；不改变既有 UI model-kinds 接口的独立推断语义。

## 5. HTTP 契约（提案）

### 5.1 读取模型列表

`GET /v1/models?include=metadata`。仅 `include` **恰好出现一次且值精确等于** `metadata` 才启用；省略、重复或其他值沿用原处理方式并保持原字段集合，避免把原先被忽略的查询参数变成新错误。不是管理写接口，不需要 `config_revision`；不新增刷新或查询全目录的公共 API。

示例数字和模型均为虚构，且假设它们满足第 4 节的全部一致性条件，不代表任何真实模型：

```http
GET /v1/models?include=metadata HTTP/1.1
Authorization: Bearer <调用方凭据>
```

```json
{
  "object": "list",
  "data": [
    {
      "id": "example-model",
      "object": "model",
      "owned_by": "auto-model-key-router",
      "display_name": "Example Model",
      "reasoning": true,
      "context_window": 128000,
      "max_output_tokens": 2048,
      "modalities": {"input": ["image", "text"], "output": ["text"]}
    },
    {"id": "private-alias", "object": "model", "owned_by": "auto-model-key-router"}
  ]
}
```

所有新增字段均独立可省略，`null` 不在此契约中。示例没有 `kind` 是有意的。按既有规则维持成功 `200` 的列表外壳和顺序；目录无数据不应变 `503`。认证、已停用 Key、装配错误保留现有错误状态和信封；不因参数启用另一路认证。新响应设置 `Cache-Control: private, no-store`，中间缓存不得复用跨凭据结果；不新增全局结果缓存或共享 ETag，默认请求的现有行为不因本文被改变。`POST` 等同路径其他方法的现有分发语义不动。

### 5.2 TypeScript 消费形状

```ts
type ModelKind = "text" | "image" | "video" | "tts" | "stt" | "embedding" | "rerank";
type Modality = "text" | "image" | "audio" | "video" | "pdf";
interface V1Model {
  id: string;
  object?: "model";
  owned_by?: string;
  display_name?: string;
  reasoning?: boolean;
  context_window?: number;
  max_output_tokens?: number;
  modalities?: { input?: Modality[]; output?: Modality[] };
  kind?: ModelKind;
  [key: string]: unknown;
}
```

前端在网络边界运行时校验类型并保留 `false`，不能只靠 TypeScript 断言；不认识的新增字段忽略。`id` 仍是唯一选择值和请求值，显示名仅为标签，不作为去重键。旧服务忽略新增查询参数、仍返回旧形状时继续正常使用。响应异常的单个可选字段不应导致整个列表消失。

## 6. 缓存、并发、故障与安全（提案）

| 情况 | 对外结果及状态变化 |
| --- | --- |
| 冷启动或从未成功抓取 | 显式请求仍返回原列表，每项不带新元数据；后台按现有方式预热或在读取到期时触发，绝不等待网络。 |
| 200 且目录与派生索引校验通过 | 在锁外解析、构造不可变价格/类型/元数据索引，整体校验后以同一版本原子发布；一次请求仅读一个元数据快照，不能混合不同刷新版本。 |
| 304 且已有快照 | 保留三个索引及数据更新时间，延长新鲜期；拟增加/更新内部“最后复验成功”时间并清除最近错误状态。304 但无快照视为失败。注意当前 304 路径只延长 `nextAt`，错误状态清理是拟新增行为。 |
| 超时、非 2xx、无效 JSON、超出大小上限、无有效价格索引 | 沿用当前整体提交门槛与失败退避，保留**完整旧快照**，不部分覆盖价格、类型或元数据；没有旧快照则返回基础列表。字段级坏值不影响有效兄弟字段，也不视为全局失败。 |
| 已有快照但刷新失败 | 继续返回旧快照中可用且仍满足当前配置/权限匹配的数据；旧值是可能过期的第三方参考，不能用于限制请求。只在管理界面显示“目录更新失败，显示上次成功数据”。 |
| 配置热重载、权限变更 | 每次请求使用其 lease 的同一配置/KeyPool 快照重新生成受权名称与目标匹配；仅共享公开目录快照，不缓存跨用户最终响应。已开始的请求可按旧 lease 完成，新请求使用新配置，不保证撤销已发出的响应。 |
| 并发读取/刷新 | 三种索引共享现有 `refreshOnce` 同步入口、`loading` 闸门及 `nextAt` 二次检查；定时、惰性触发不得各自下载。若未来引入手动刷新，也必须走同一闸门；读取不持锁做网络或逐项复杂解析。 |

源站是外部不可信输入。拟给 HTTP 正文设 **16 MiB** 上限，超限作为刷新失败并保留旧快照；复用 90 秒超时和条件请求。仅允许 HTTPS、固定源同主机的有限重定向（最多 3 次），禁止向其转发客户端 Authorization、访问 Key、模型名或本地配置；该限制同时影响现有价格抓取，实施前需覆盖真实源重定向兼容性。目录字符串不可拼入 HTML，UI 作为文本渲染；日志只记录去敏的错误类别、时间和数量，不记录 Key、请求头、上游完整响应和提示词。`/ui/model-kinds.json` 是现有公开分类工具，不得用于输出配置模型清单或新增受限用户可访问的真实路由映射。

可观测性尽量复用已有 `/ui/pricing.json` 的 `updated_at` / `error`（现有形状见 `internal/pricing/pricing.go:433-481`）：完整权限管理页面显示最后成功数据时间、刷新错误类别和下一步提示；不要向普通 `/v1/models` 用户附带内部错误。拟记录拉取成功/失败次数、耗时、快照年龄、命中/未命中/冲突的**聚合**数量；不按模型 ID、Key 或工作空间创建高基数指标。指标形式沿用现有日志/指标机制，不额外暴露无鉴权状态接口。

性能边界：单次上游解析与建索引按目录条目数线性，并预计算每个精确 ID 的字段共识；每次请求将当前 lease 内的模型名、任务名及相关启用目标扫描一次形成临时索引，再对已授权名字逐项查表，避免每个名字再次线性扫描全部配置。请求复杂度为配置条目与目标数量加授权名字数；不扫描全量远程目录，不同步网络，与价格/分类共用一次下载。实现阶段用固定 8,000 模型夹具及 1,000 个授权名字验证不会重复下载和出现明显退化，具体耗时以同机基线比较，不把设计值写成已测结果。

## 7. UI 表达与兼容

- Playground 首先消费授权后的 `V1Model[]`，以 `id` 选中和提交；展示“显示名 · ID”、窗口、模态、推理标签（仅字段存在时），并标注“来源：models.dev，实际能力以上游为准”。没有显示名就只显示 ID；没有窗口显示“暂无资料”，`reasoning:false` 显示“目录标记：不支持推理”，缺失不显示负面标签。
- `kind` 缺失时不将其自动视为 `text`。既有 `/ui/model-kinds.json` 的规则分类可作为另行标明“推测分类”的辅助信息，但不能伪装成目录已知值、用于剔除列表或覆盖返回的显式元数据。
- 保留当前已选择 ID、输入草稿与焦点；刷新元数据不改默认模型或发起模型调用。旧后端或目录不可用时依然能选 ID。禁止把 `/v1/models` 的 401/403 回退成更宽的管理模型列表；仅在已确认完整管理身份且非鉴权失败时保留既有管理 UI 的受控回退，受限用户任何回退不得扩大原授权列表。
- 不将额外的 `/api/models` 结果或公开 model-kinds 结果合并成受限列表；工作空间的推理 Key 必须使用服务器认定的空间而不是信任客户端头。面板 Key 不获得推理或全局管理权限。
- 不改变本期 Agent 集成输出；尤其 Pi 的旧固定值是既有兼容债，不得作为本专题“已知窗口”。未来调整 Pi/Codex/Claude 时必须在临时 HOME 验证目标版本的缺省值、必填字段、更新前预演、备份/回滚及未知值行为，不能在后台静默重写本地配置。

## 9. 实施顺序与文件清单（提案）

1. **目录数据与刷新**：在 `internal/pricing/pricing.go` 扩展同源只读索引、字段验证、一致性计算、正文/重定向限制及快照/304 状态；优先复用已有 `internal/pricing/pricing_test.go` 和 `internal/pricing/http_test.go` 的固定抓取接缝，覆盖 MC-03/04/09/10/12。是否把纯解析逻辑拆入同包新文件，以可读性为准，不新增依赖或通用框架。
2. **服务端接线**：在 `internal/server/handlers.go` 的既有鉴权及名字筛选之后增量渲染可选字段；必要时从现有 `internal/config/model.go` 的配置快照查询直接目标和任务冲突，不修改配置协议。扩展 `internal/server/handlers_test.go`、`internal/server/reload_test.go`、`internal/server/quota_freeze_test.go` 覆盖权限、热重载、冻结与兼容；不更改 `internal/server/modelkinds.go` 的公开语义。
