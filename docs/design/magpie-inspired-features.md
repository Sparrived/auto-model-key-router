>
> 调研对象：[`yetone/magpie`](https://github.com/yetone/magpie)，对照提交
> [`1f04ed2193996ecbce278df0e299af9f1e6f0dd0`](https://github.com/yetone/magpie/commit/1f04ed2193996ecbce278df0e299af9f1e6f0dd0)。

## 1. 背景与结论

Magpie 值得学习的核心不是 Agent 或功能数量，而是把网关能力组织成四个连续动作：

1. **能接入**：调用方能找到地址、凭据、协议和模型，并能复制可运行示例。
2. **能选择**：用户能在 AMKR 内选择客户端默认模型，而不是理解全部上游拓扑。
3. **能解释**：一次请求为什么落到某个 Provider / 上游 Key，候选为什么被跳过，可以核对。
4. **能约束**：分发给项目或成员的调用方凭据不仅有权限范围，还有可核对的周期预算。

AMKR 保持“轻量、单二进制、本地与团队兼用、任务治理”的定位，不演变为桌面 Agent 管理平台。

## 4. 明确不做

- 不实现 Magpie 的菜单栏、TUI、Profiles、资料库、搜索/生图工具、远程同步或订阅凭据发现。
- 不引入 Bun、Node、JavaScript 插件运行时或新的模型运行时依赖。
- 不做嵌套路由组、意图路由或 LLM-as-judge。
- 不在本轮加入提示词隐私脱敏；它需要独立的安全设计与验收。
- 不为了界面整齐而编造上下文窗口、模态、价格或额度；未知就是未知。
- 不改变旧配置、旧客户端和未启用新功能时的路由行为。

## 5. 共同契约

### 5.1 配置与兼容

1. 新配置全部可选；缺省、旧版本配置和未配置对应功能时，行为保持原样。
2. 管理写接口沿用现有权限与 `config_revision` 机制；冲突保留用户草稿，不静默覆盖。
3. 配置解析、校验、规范化、导入导出、修复与热重载必须同时覆盖，不能只改结构体。
4. 访问密钥轮换不改变其预算身份；删除后历史指标仍保留。工作空间改名是否保留预算身份由专题文档明确。
5. 新错误沿用它所属协议的错误信封，并提供稳定、可测试的原因；不得泄露完整凭据。

### 5.2 权限与隐私

1. 完整管理凭据可以读取全局诊断；受限调用方只能读取自己的预算与选路记录。
2. 工作空间面板 Key 不因新功能获得推理权限；访客看板不能借诊断接口越权读取其他调用方数据。
3. 选路解释只保存元数据：模型名、Provider ID、上游 Key 的显示名/脱敏尾部、状态码、原因和时间。
4. 不保存提示词、回复正文、工具参数、Authorization、完整 API Key 或管理密钥。
5. 新协议入口必须复用同一条鉴权、工作空间、预算、路由、指标和追踪链路，不能形成旁路。

### 5.3 时间与用量

1. 现有指标时间按北京时区记录；新功能必须显式处理既有时间格式和时区转换，自然日/周/月边界在专题契约中明确，不能擅自改写历史口径。
2. Token、缓存 Token 复用现有指标；现有估算费用由前端依据价格目录计算，若用于服务端限额，必须明确价格快照、缺价和计价口径，不能假定指标库已保存费用。
3. 流式请求在真正结束时完成用量与追踪收尾；现有指标按上游尝试计数，客户端断开和重试要区分每次尝试与整次请求，不能重复结算同一次尝试。
4. 费用预算是基于已知价格的估算约束；价格未知时的行为必须显式、可观测，不能按 0 元放行。

### 5.4 UI 表达

1. 统一使用“上游 Provider Key”和“下游客户端 Access Key”；工作空间沿用“推理 Key / 面板 Key”。
2. 空状态说明缺什么并给出下一步；接口失败与无数据分开；错误文案包含可执行恢复动作。
3. 选路解释用工程事实，例如“key-01 因 429 冷却 58 秒，本次切换至 key-02”，不使用“智能地悄悄处理”。
4. 页面同时只保留一个实心主按钮；危险操作使用非实心危险样式并二次确认。
5. 编辑在现有 Sheet / 行内区域完成，低频配置进入 Advanced；轮询不得丢失草稿、焦点和展开状态。
6. 视觉、图表、键盘与响应式行为继续遵守 `ui.md` 和 `docs/design/webui-v7.md`。

## 7. 端到端验收总矩阵

| 编号 | 用户场景 | 必须观察到的结果 |
| --- | --- | --- |
| E2E-01 | 旧配置启动并完成原有 Chat / Messages / Responses 调用 | 不启用新功能时，路由、响应与权限行为不变 |
| E2E-02 | 为下游 Access Key 设置周期 Token 预算并持续调用 | 页面读数与请求记录一致；超限请求被阻止且没有上游调用 |
| E2E-03 | 并发请求接近预算边界 | 不出现重复扣减、负数用量或无限重试；允许的超调边界与专题契约一致 |
| E2E-04 | 一次请求经历冷却/冻结、候选切换后成功 | 调用方获得请求 ID；详情能解释每个候选的排除或尝试原因 |
| E2E-05 | 受限 Key 查询诊断 | 只能看到自己的记录；其他 Key、工作空间和完整管理数据不可见 |
| E2E-06 | 新用户按接入向导配置受支持客户端 | 能复制运行示例；默认模型正确；应用前可查看差异，断开/回退恢复原配置 |
| E2E-07 | 使用受限凭据请求模型目录 | 只返回已授权模型；元数据缺失时不影响列表与调用 |
| E2E-08 | Gemini 客户端发送普通与流式请求 | 返回 Gemini 形状；鉴权、预算、选路、指标和追踪与其他协议一致 |
| E2E-09 | 使用 `usage` / `pace` 并移除额度信号 | 排序符合公式；无信号时按文档退化，不崩溃、不随机漂移 |
| E2E-10 | 管理写发生冲突、上游超时、客户端中流断开 | 草稿与旧配置不丢；指标/追踪收尾一次；错误可行动且不泄密 |

## 8. 交付与验证边界

- Go 代码保持中文“为什么”注释，执行 `gofmt`、相关包测试、`go test ./...` 与 `go build ./...`。
- 前端源码仅改 `web/src/`，执行 `npm run typecheck` 与 `npm test`；本任务不修改 `webui/` 构建产物。
- 不新增无业务价值的测试文件；优先在现有测试套件补充覆盖，并由独立子代理按真实用户操作链复核。
- 不访问真实付费上游，不使用真实账号或密钥做测试；采用本地假上游与临时 HOME/配置/数据库。
- 不执行 `git add` / `commit` / `stash` / `checkout`；最终列出改动、证据和未验证边界。
