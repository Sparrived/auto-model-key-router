## 可直接执行的硬性提示词

你是一名擅长高密度管理工具与数据可视化的前端设计工程师。请重构 Auto Model Key Router 的 WebUI，严格采用「赤陶暖色数据工作台」视觉系统。

这不是旧界面换色，也不是营销展示页。可以重新设计应用外壳、页面布局、组件造型与信息层级，但必须保留实际产品功能、API 契约、权限边界、真实数据口径和安全确认流程。

### 一、视觉方向与优先级

1. 使用 A 的配色：稳重的赤陶背景、奶油白表面、燕麦色次级表面、深棕文字、克制的深赤陶主操作。
2. 使用 B 的布局：独立悬浮导航、直接铺在暖色画布上的内容、主次指标卡、宽窄搭配的图表模块、全宽数据表。
3. 不采用 A 的「所有内容包在一整块白色面板内」布局；不沿用 B 的粉橙主指标色。主指标强调底色采用低饱和浅陶色。
4. 视觉活力来自不同信息权重、比例与留白，不来自随机配色、不规则瀑布流或持续动画。
5. 功能正确性、权限安全与可读性优先于装饰性细节。在满足上述前提后，优先保持整体风格识别度。
6. 本视觉规范替代项目原有 Material Design 风格规范。实施时同步更新旧设计文档，禁止保留旧紫色/青色主题并叠加暖色补丁。

### 二、颜色角色：必须统一为语义 Token

使用以下颜色作为基准。允许为无障碍对比度做小幅明度调整，但不得改变暖陶色、奶油白、深棕文字的核心关系。

```css
:root {
  --ui-canvas: #c9967a;
  --ui-surface: #faf8f5;
  --ui-surface-soft: #f2eae2;
  --ui-surface-emphasis: #edc5ae;

  --ui-text: #49392f;
  --ui-text-muted: #7b6558;
  --ui-text-on-canvas: #423127;
  --ui-text-selected: #854332;
  --ui-focus: #423127;

  --ui-action: #a34f3d;
  --ui-action-hover: #8e4434;
  --ui-on-action: #fff8f2;
  --ui-divider: #e8ddd4;
  --ui-input-outline: #977b68;

  --ui-success: #596044;
  --ui-success-bg: #e7eadf;
  --ui-warning: #866022;
  --ui-warning-bg: #f3e6c9;
  --ui-danger: #923f38;
  --ui-danger-bg: #f5ddd6;

  --chart-primary: #ba725c;
  --chart-secondary: #717859;
  --chart-tertiary: #9b754f;
  --chart-neutral: #8c6854;
}
```

- 页面背景必须明显可见，默认使用 `--ui-canvas`，不得为了信息密度把全站背景改成白色。
- 主文字为深棕，不使用纯黑；暖色背景上的文字使用专门的 `--ui-text-on-canvas`，不得直接复用浅灰辅助色。
- 主按钮采用深赤陶底与奶油色文字。浅陶色卡片采用深棕文字，不使用浅珊瑚底配白色小字。
- 导航选中底色采用浅陶色，文字使用 `--ui-text-selected`。区分「主按钮色」与「浅色底上的选中文字色」。
- 成功与告警语义色仅用于状态、提示和必要图表系列，不可扩展为页面背景或大面积冷色卡片。
- 不同分类图表允许扩展低饱和陶色、沙色和橄榄色，不可只循环三种颜色造成无法辨认；类别应有稳定标识，并以图例、标签或线型辅助区分。
- 普通文本对比度至少 4.5:1；大字与必要非文本图形至少 3:1。弱分割线不得充当输入框或交互组件唯一的边界识别方式。

### 三、全局布局

#### 桌面端

- 暖色画布留出约 20–28px 外边距。
- 左侧采用约 224–240px 宽的独立奶油白导航面板，圆角 24px，柔和阴影；保持完整导航分组、当前页定位与服务状态。
- 导航允许内部滚动，以适应全部入口；底部状态不能遮挡最后几个导航项。
- 内容区直接铺在画布上，不再外包一块巨大的白底总面板。
- 页头包含标题、必要说明、当前状态与本页工具；不要新增无意义的欢迎语、大 Hero 或营销文案。
- 内容区使用规则化响应式栅格，卡片间距约 16–24px；同排卡片边缘对齐。不使用随机瀑布流。
- 大屏利用可用宽度，但为长文本阅读和超宽图表设置合理上限，避免人为留下大片空洞。

#### 响应式

- 平板减小列数与侧栏占用，宽图表、长列表自然换行。
- 手机将主导航转换为可打开的抽屉，不强行塞入 14 个底部标签。
- 指标卡按宽度转换为双列或单列；主指标仍然优先，不依赖超大字号撑版。
- 数据表只允许容器内横向滚动，整页不得横向溢出。
- 表格内可弱化次要列，但完整值和全部操作必须仍可访问；长模型名应支持查看完整内容与复制。
- 至少检查 360、768、1024、1440、1920px 视口。

### 四、概览页的具体组织方式

1. 页头：标题、简要说明、连接状态、复制服务入口、统计窗口与刷新操作。
2. 第一排：4 张主指标卡。当前 RPM 为主卡，宽度约为其他卡的 1.2–1.35 倍，使用浅陶色底；当前 TPM、成功率、估算成本使用奶油白。卡片同排等高。
3. 第二排：主趋势图与模型/Token 构成或资源健康模块，按约 8:4 比例布局；窗口与桶宽说明保留。
4. 次级指标带：窗口请求、重试率、Token 用量、缓存命中率、平均耗时、平均首字。保留现有读数，不为简化界面删去指标。
5. 请求流：独占整行，保持时间、路由/模型、请求形态、来源、Token、结果、耗时等实际字段。列宽优先保障长模型名与来源信息。
6. 热力图、实时脉搏、结果构成、状态码、排行、统一模型入口与运行详情按任务优先级放在后续区块；可合理分组，但不得悄悄移除。
7. 所有重排只改变显示层次，不改变统计定义。实时 60 秒速率、用户选择窗口和固定 7 天热力图必须各自明确标识。

### 五、其他页面的布局要求

- 供应商、模型路由：在同一暖色画布内使用对象列表与详情模块；列表、表格、编辑表单分别进入奶油表面，不把配置对象做成巨型展示卡。
- 对象较多时使用搜索、筛选或分组组织；这些能力必须真实可用，不画假搜索框或不可用的快捷操作。
- 列表行、状态、Key 能力、绑定模型、优先顺序应清楚可扫读。不能为了大圆角给每一行套上独立阴影卡。
- 路由关系可用简洁的有向链路辅助理解，但必须呈现真实目标或明确的策略示意，不以单一路径误导多目标路由。
- 用量、成本、工作空间：复用相同栅格、图表容器、筛选工具与配色规则。桑基图、排行、金额覆盖说明保留。
- 服务日志：使用浅暖表面与可读等宽文字，保留搜索、级别筛选、暂停刷新、自动跟随等功能；内容区优先，不引入黑底终端视觉。
- 试验场：输入、参数、输出按任务流程组织，同一套视觉规则下可采用更紧凑布局。
- 统一模型、任务路由、访问密钥、账号资源、集成、设置：统一表单、列表和确认组件，不因页面用途不同回到旧主题。
- 登录、工作空间嵌入面板及实际仍在使用的独立入口必须一并覆盖；若有遗留页面，先确认是否仍可达，不以文件名猜测是否可以删掉。

### 六、组件、排版与材质

- 大模块圆角 24px，普通卡片 16–24px，输入与按钮 10–12px，紧凑标签 6–10px；状态标签可用胶囊。不可所有组件都做成胶囊。
- 卡片内边距通常 20–24px；密集表格与对象列表可以更紧凑，外部视觉节奏保持统一。
- 普通边框最多 1px，采用暖灰棕色；表格用细分隔线，不使用完整的粗网格。
- 阴影应柔和、漫射、低不透明度，例如 `0 10px 30px -6px rgba(83,49,31,0.10)`。模态层可以更强，但不得硬边或浓黑。
- 不使用多层厚重拟物内阴影、玻璃模糊、金属高光、背景纹理与装饰性渐变。
- 字体使用可靠的中文/系统无衬线组合，不依赖外网字体才能正确显示。代码、Key 指纹、模型 ID 使用等宽字体。
- 页面标题约 24–30px，主读数约 32–40px，正文 14–15px，辅助信息 12–13px；图表刻度最低 11–12px，不牺牲可读性。
- 所有变化中的数值使用 `tabular-nums`，单位、金额精度、百分比与数值主次明确，避免数据刷新时跳动。
- 主要操作显示文字，不把关键功能全藏在无标签图标里。
- 空态、加载、错误、断连、禁用、未探测、冷却、未定价、保存中等状态必须完整设计。

### 七、交互规则

- hover、active、focus-visible、selected、disabled、busy 必须可区分。
- 使用约 160–220ms 的颜色/透明度/阴影过渡，按需提供轻微按下反馈；不要给全部容器使用 `transition: all`。
- 静态数据卡片悬停不抬升、不缩放，不制造「可点击」的误导。
- 聚焦反馈必须明显。无障碍焦点 outline 不属于禁止的粗边框，但不得当作默认装饰。
- 支持键盘导航、明确的表单标签、错误关联、模态焦点管理与恢复，遵守 `prefers-reduced-motion`。
- 实时更新只更新必要的数据区域，保留输入焦点、表单草稿、选中对象、已展开详情、筛选项和滚动位置。
- 高频刷新不得造成卡片闪烁、列表反复跳动或布局位移。

### 八、功能与数据红线

- 不修改 API 路径、字段、鉴权与访问范围，不因 UI 重构提升任何凭据权限。
- 保留供应商、Key、模型能力探测、路由优先顺序、统一模型计划、任务路由、工作空间与访问密钥的现有业务语义。
- 保留配置版本校验、连带影响预演、删除确认、保存失败反馈等安全流程。
- 敏感 Key 默认隐藏；复制/显示流程仍受现有权限限制，不在日志、截图或示例中泄露真实密钥。
- 无数据与数值 0 必须区分。未就绪、失败、无定价不显示虚假的 0 或成功状态。
- 成本依然是估算且可能部分覆盖，保留定价来源、覆盖率和未知项，不包装成实际账单。
- 图表口径、图例和状态语义保持一致。流量增长不自动标为异常，耗时增加与成功率增加不能使用同一好坏极性。
- 不使用概念稿中的样例数值、假搜索、假菜单、假状态或演示图表作为生产实现。

### 九、技术落地与质量要求

- 优先沿用现有原生 ES module 与 Go 静态资源嵌入方式。为视觉重构不强行引入 React、Tailwind 或新的运行依赖。
- 先建立统一 Token、外壳与共享组件，再按模块调整页面结构和图表主题。
- 审查所有硬编码颜色、SVG 图表属性、独立 HTML 入口、行内样式和旧主题引用；不能只替换根变量。
- 使用清晰的组件职责与可维护样式，避免一个选择器不断覆盖另一个选择器的主题补丁。
- 落地时同步项目设计规范与实现，避免旧 Material 文档与新主题同时指挥后续修改。
- 尊重现有未提交修改，不覆盖、不归入本次提交。
- 如需提交，按模块拆分，采用 Conventional Commits；类型与作用域使用常规英文，描述、正文与脚注使用中文，例如 `feat(webui): 重构赤陶暖色应用外壳`。
- 不新增无用测试文件。涉及界面验收时，派发普通子代理模拟真实用户操作，而不是只断言 DOM 字符串；未获用户要求，不创建 Agent Teams 或持久队友。
- 优先复用已有构建/检查/测试手段，并由子代理独立走查实际页面：导航、时间切换、添加和编辑、探测、保存取消、复制、删除影响确认、错误断连、键盘、窄屏与轮询状态保持。危险操作只使用隔离测试配置与假凭据，禁止触碰真实资源。
- 子代理必须报告实际执行环境、浏览器/视口、步骤、结果及证据；若无法实际运行浏览器，应明确标注未验证，不得把代码阅读称为真实操作测试。
