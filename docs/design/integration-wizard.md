# 客户端接入向导与默认模型

> 状态：设计稿；实现状态以代码和验收结果为准。本文是客户端接入与默认模型的专题设计稿，不改变路由策略。

## 1. 背景与目标

现有集成页分别展示 Claude Code、Codex、Pi Agent 的目标文件、状态和备份；应用时服务端将全部可用模型写入客户端，确认后才修改文件。实现见 `web/src/pages/integrations/index.tsx:24-50,125-165,199-275`、`internal/api/handlers_ops.go:480-565`、`internal/agentconfig/agentconfig.go:317-447`。现有页面的“变更字段”是静态清单，不是逐字 diff；配置应用实际使用本地管理 Key，不能描述成受限 Access Key。

目标：在一个页面说明本机入口、下游凭据、模型与协议示例；可为支持的客户端选择新会话默认模型和可选推理强度；保留应用确认、备份和回退。选中的客户端默认模型是启动偏好，不改变 AMKR 全局模型路由或正在运行的会话。

## 2. 范围与不做事项

- 支持 Claude Code、Codex、Pi Agent。模型来自服务端当前启用上游 Key 的可调用名和别名（临时冻结不移除）；完整列表与 `/v1/models` 和现有 `availableModelNames` 一致。用户可搜索模型并明确选择“沿用现有行为”。
- 可选推理档位仅针对相应客户端官方支持的设置；不传时保持原有逻辑，绝不推断上游真实能力或承诺档位一定生效。
- 独立的手动接入示例使用占位符 `YOUR_ACCESS_KEY`；提示先在访问密钥页创建并按可见明文一次性保存。页面不读取、复制、显示真实完整密钥。现有自动应用仍使用服务端的本地管理 Key，界面必须明确其完整权限，不伪称受限 Key。
- 不做客户端发现、自动安装、跨机器写配置、WSL 扫描、Profiles、自动重启或凭据发现。本阶段不把用户提供的密钥传给服务端写入客户端。

## 3. 用户流程与界面

1. 入口区域展示当前 AMKR 地址；监听通配地址时用于**服务所在机器本机**的地址为 `127.0.0.1`。从其他机器访问时应使用服务机器可达地址，不能把浏览器所在机器的回环地址当作远程服务地址；不自动暴露到局域网。
2. 展示 OpenAI 兼容、Anthropic 两种协议的 Base URL、模型及配置示例，使用占位凭据，附复制按钮和“先创建访问密钥”的导航提示。地址不可得、模型为空、接口失败分别说明原因和下一步。
3. 每个 Agent 选一个默认模型或“保留现有默认模型”，可选配置该客户端支持的推理档位；选项为空时不发送对应字段。列出会改动的文件和字段，并注明这是字段清单而非逐字差异。应用前确认文件、模型、凭据权限和备份影响；取消不得写文件。
4. 成功后刷新状态；失败保留模型/档位选择并显示具体错误。回退前说明会恢复备份并替换当前接管内容；若用户接管后自行修改过文件，必须明确提示回退会覆盖当前文件。
5. 切换新模型后告知：对新会话生效，客户端自身命令行/项目配置可能优先；浏览器刷新或轮询不得重置当前选择。

## 4. 提议接口契约

### 4.1 模型读取

复用 `GET /v1/models`（按调用凭据权限过滤）或已有管理模型列表，不在前端猜测禁用状态。管理界面使用完整管理权限时可列所有对外可调用模型；网络失败不能当作空列表。服务端应用时必须以最新配置再次校验，避免列表加载后配置变化导致写入不可调用名称。

### 4.2 应用集成

沿用 `POST /api/integrations/{agent}` 和完整管理鉴权。向现有可选 JSON 请求体增加：

```json
{ "default_model": "example-model", "reasoning_effort": "high" }
```

- 请求体、`default_model`、`reasoning_effort` 均可省；省略的字段保持既有应用语义。旧 `mode` 仍接受且忽略；未知 Agent、错误类型及旧响应形状保持兼容。
- 非空 `default_model` 必须与当前可用模型 ID / 别名 / 已配置 `unified-model` 精确匹配；空串、未知或已停用模型报明确错误，且不写任何文件。
- `reasoning_effort` 只接受当前 Agent 支持的已知字符串；非法值和该 Agent 不支持的值拒绝，不能静默忽略。可选档位不代表模型真实支持，UI 提示取决于客户端及上游。服务端不得信任前端校验。
- 现有 `config_revision` 在运维集成请求中并不参与并发校验（`internal/api/handlers_ops.go:86-101`）；如新增此保证须实现真实比较，不能只加字段宣称已受保护。
- 当前接缝是 `OpsIntegrations.Configure(agent,cfg)`（`internal/api/handlers_ops.go:132-147`）；扩展时保留旧调用路径并在未接线或无选项处理器时明确报错，不能丢掉请求选项后返回成功。

### 4.3 客户端字段

| 客户端 | 默认模型 | 可选推理档位 | 注意 |
| --- | --- | --- | --- |
| Claude Code | 用户级 `settings.json` 的 `model` | 仅在核验对应客户端设置语义后写入；未核验前不展示 | 不改 `ANTHROPIC_DEFAULT_*` 角色模型，避免所有子任务被钉死 |
| Codex | `config.toml` 顶层 `model` | `model_reasoning_effort`，取值以客户端支持列表为准 | 不因改默认模型覆盖用户的 `review_model`；保留 TOML 注释和无关表 |
| Pi Agent | Agent 目录的 `settings.json` 中 `defaultProvider=amkr`、`defaultModel` | `defaultThinkingLevel`，具体值以客户端支持列表为准 | 这是现有 `models.json` 外新增的文件，必须纳入同一备份、失败回滚、接管状态与回退 |

官方参考：[Claude Code 模型配置](https://code.claude.com/docs/en/model-config)、[Codex 配置参考](https://developers.openai.com/codex/config-reference)、[Pi 设置](https://github.com/badlogic/pi-mono/blob/HEAD/packages/coding-agent/docs/settings.md)。官方文档可能随客户端版本演进，需以受支持版本实际验证。

## 5. 备份、原子性与并发

- 沿用 `internal/agentconfig/agentconfig.go:345-446` 的备份与附加文件机制。首次应用记录原内容及是否存在；重复应用且文件仍是 AMKR 所写时保留最初快照；用户已编辑则按现有行为重新确定快照。
- Pi 的 `settings.json` 只有显式选择模型/档位时才加入附加目标；读取、JSON 校验和目标计算必须在任何落盘之前完成。写任一文件失败应按现有快照机制恢复已经写过的文件与备份。
- 若已有接管但旧备份未记录新增的 Pi 文件，新增文件的原始状态必须单独备份；回退恢复该文件或删除原本不存在的文件。不得把备份缺失等同于可覆盖。
- 配置文件、备份及鉴权文件可能包含密钥；预览和错误不能输出文件正文或完整密钥。测试必须使用临时 HOME/路径，不访问用户真实配置。
- 用户文件可能在预览与应用之间变化；真正逐字 diff 预演需包含文件版本校验、遮罩与冲突处理，不能用静态字段列表冒充。该能力尚待实现，首版明确标为“变更字段”。

## 6. 验收矩阵

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| I-01 | 旧客户端空请求体、旧 `mode` | 结果与原行为一致；仍注入可用模型 |
| I-02 | 选择 Claude/Codex/Pi 的有效模型并应用 | 对应默认字段准确写入；无关配置保留；只影响新会话 |
| I-03 | 模型不存在、已停用、档位非法 | 返回明确错误；目标和备份均不变 |
| I-04 | Pi 首次应用、重复应用、回退 | 两个文件均记录状态，最终恢复原字节或删除原本不存在文件 |
| I-05 | 某附加文件写入失败 | 主文件及已写附加文件回滚，不留下半套接入 |
| I-06 | 未选择模型/推理强度 | 不覆盖用户已有值；沿用原逻辑 |
| I-07 | 本机/远程打开页面 | 不把远程用户的 `127.0.0.1` 当服务地址；复制示例只含占位密钥 |
| I-08 | 取消确认、列表刷新、接口失败 | 不写文件；草稿保留；错误与下一步可见 |
| I-09 | 回退前已有用户编辑 | 明确提示覆盖风险；取消不改文件 |
| I-10 | 无认证或运维接口关闭 | 不执行应用/回退，显示可操作的原因 |
